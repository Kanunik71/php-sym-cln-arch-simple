# Architecture Decision Records

ADR фиксирует **значимое архитектурное решение**: контекст, выбранный вариант,
последствия и отвергнутые альтернативы. Один файл — одно решение.

## Когда заводить

- выбор между несколькими подходами (паттерн, библиотека, протокол);
- отказ от ранее выбранного подхода;
- решение, которое будущему читателю будет непонятно без объяснения.

Рутинные изменения и детали реализации ADR не требуют — для них есть спеки.

## Формат

- Файл: `NNNN-kebab-case.md`, номер сквозной (`0001-use-ulid-for-ids.md`).
- Шаблон: [`_template.md`](_template.md).
- Статус: `proposed` → `accepted` / `rejected` / `superseded`.
- ADR не редактируется после принятия: при изменении решения создаётся новый
  ADR со ссылкой `supersedes` / `superseded by`.
