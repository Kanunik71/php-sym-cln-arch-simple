# Правила работы в проекте `cln-arch-sym-simple`

## Язык общения

- Отвечай пользователю на русском языке.
- В коде — всё на английском: идентификаторы, имена классов/методов, комментарии и docblock-и, строки пользовательского интерфейса и API, ключи и значения wire-контрактов. Сообщения коммитов тоже на английском.
- На русском допустима документация: тексты `AGENTS.md`, спеки OpenSpec (`openspec/specs/`) и артефакты изменений (proposal, design, tasks).

## Артефакты OpenSpec

- Язык и структурные заголовки артефактов заданы в `openspec/config.yaml` (`context` и `rules`) — следуй им при создании proposal/design/tasks/spec-дельт.
- `openspec/specs/` описывает **фактическое** поведение кода (`api/src`) и тестов (`api/tests`) — это источник истины.
- `api/AGENTS.md` (+ `api/src/Application/AGENTS.md`, `api/src/Infrastructure/AGENTS.md`, `api/tests/AGENTS.md`) описывает **целевое** состояние архитектуры — используй его при проектировании и реализации изменений, но не переноси его в спеки как описание текущего поведения.
- Расхождения кода с `AGENTS.md` фиксируй в секции `## Notes` соответствующей спеки.

## Порядок работы над задачей

Ведает workflow `task-flow` (`.agents/skills/task-flow/SKILL.md`): анализ по тексту
запроса → утверждение плана → реализация по `tasks.md` → тесты → `verify` →
`reviewer` → `critic` → `verification.md` → архивация. Полное описание шагов —
в `README.md` («Поток»).

- Имя change — `<slug>`, задача трекера в него не входит. Трекер подключается
  только по указанию в тексте (строка `**Трекер**:` в `proposal.md`); его
  отсутствие — норма, а не нарушение процесса.

- Скиллы воркфлоу лежат в `.agents/skills/` (общий для инструментов корень,
  генерируется `openspec update` — не правь их руками), субагенты проверки —
  в `.opencode/agents/` (роль каждой описана текстом, переносима между
  инструментами; механизм субагентов — нет).
- Артефакты change используют проектную схему `openspec/schemas/cln-flow/`
  (форк `spec-driven` с добавленным артефактом `verification`): правки формата и
  инструкций — там, конвенции и правила — в `openspec/config.yaml`.
- Изменение готово только при зелёном прогоне **на текущем дереве**: правка после
  прогона обнуляет его доказательства.
